# 调研报告 #3：客户自助 Dashboard + 收款方案

> 你问："客户自助 Dashboard，要怎么引导用户去付费呢？现在引导他们去爱发电付费。是需要自建网站还是怎样？"
> 我答：**先不要自建。在爱发电基础上加一个轻量的「license 自助查询页」就够了**。下面是详细对比 + 实施路径。

---

## TL;DR

| 方案 | 适合阶段 | 实施成本 |
|---|---|---|
| **A. 完全靠爱发电 + 手动发 key**（你现在这样）| 0–50 付费用户 | 0（但每天要手动） |
| **B. 爱发电 + 自助查询页**（**推荐立刻做**）| 50–500 付费用户 | 1 天 |
| **C. 爱发电 webhook 自动发 key + 自助查询页** | 500–2000 | 2-3 天 |
| **D. 自建 landing 页 + Lemon Squeezy（国际）+ 爱发电（国内）** | 2000+ 或你想做国际 | 1-2 周 |
| **E. 自建完整 dashboard（登录 + 订单 + 设备 + 配额）** | 5000+ | 1-2 个月 |

**建议路径**：A → B → C → D。**不要跳级**。每一步都把营收提一个台阶之后再升级到下一档。

---

## 1. 现状评估

### 你现在的流程（推测）

1. 用户点 ProModal 里的"购买 Pro" → 跳到爱发电
2. 用户付款
3. 爱发电通知你（邮件 / app）
4. 你登录 Cloudflare Worker admin 后台，跑 `/admin/generate` 生成 key
5. 你手动通过爱发电私信 / 邮件把 key 发给用户
6. 用户在 TideLog 设置里粘贴 key 激活

### 问题

- 你必须 24h on-call 才能 5 分钟内发 key
- 用户付完款等 1 小时收 key 的体验**极差**
- 用户丢了 key 找不回（你没有方便的"查我所有 key"的入口）
- 用户换设备超过 3 台想换绑，没自助入口，必须找你

### 影响

- 单月负面用户体验事件 = 「等 key 等了 2 小时」+ 「换电脑找不到 key」+ 「3 设备满了想解绑」
- 这些事件每个都会让你**多花 5-15 分钟客服**

## 2. 五种方案对比

### 方案 A：完全手动（你现在）

| 优点 | 缺点 |
|---|---|
| 0 工程成本 | 不可规模化；客服累 |
| 完全可控 | 用户等待时间长 → 退款率高 |

**结论**：你已经在做。100 个用户以内可以撑。

### 方案 B：爱发电 + 自助查询页（推荐立刻做）⭐

**做法**：在你 Cloudflare Worker 上加一个 `/dashboard` 页面（静态 HTML + 2 个新 endpoint）。

页面上用户可以：

1. **输入邮箱 + 订单号** → 查询自己的 license key
2. **看到自己的设备列表** → 一键解绑某台设备
3. **看到 license 类型 + 到期日**

**新增 endpoint**：

```ts
// POST /portal/lookup
// body: { email, orderId }
// returns: { keys: [{ key, type, expiresAt, devices }] }

// POST /portal/unbind
// body: { email, orderId, deviceId }
// returns: { success, remainingDevices }
```

**新增表字段**：你现有的 `licenses` 表已经有 `email` 和 `order_id` 字段（schema.sql 第 7-8 行），所以这个不需要新表，只需要在发 key 的时候确保把 email/order_id 写进去。

**为什么"邮箱+订单号"而不是登录密码**：
- 不用做注册/登录系统
- 不用存密码 hash
- 用户根本不会想为一个 ¥99 的插件设密码
- 攻击者也得同时知道邮箱+订单号才能查 key

**这个方案能解决你 80% 的客服问题。** 强烈建议先做这个。

**前端代码**：单页面 React/Vue 都不需要，纯 HTML + 一点 vanilla JS 就够。50 行。

### 方案 C：爱发电 webhook 自动发 key

爱发电支持 [webhook](https://afdian.com/dashboard/dev) — 用户付款后立刻通知你的服务器。

**做法**：
1. 在爱发电后台填写你的 webhook URL（如 `https://tidelog-api.mydreamchronicle.com/afdian/webhook`）
2. Worker 新增 endpoint：收到 webhook 后
   - 验证签名（爱发电会签）
   - 根据订单金额判断是年度还是终身
   - 生成 key + 写入 licenses 表（带 email + order_id）
   - 调用邮件 API（如 [Resend](https://resend.com)，每月 3000 封免费）把 key 发给用户邮箱

**好处**：用户付款 → 1 分钟内收到 key。完全自动。

**坑**：
- 爱发电 webhook 文档质量一般，需要踩坑
- 邮件可能进垃圾箱（用 Resend 域名认证可以缓解）
- 发邮件 API 要单独签合同

**实施周期**：2-3 天

### 方案 D：自建 landing 页 + Lemon Squeezy（国际）+ 爱发电（国内）

如果你想做国际市场，**必须**接 Lemon Squeezy 或 Polar。爱发电不支持 PayPal / 信用卡 / Stripe，海外用户付不了。

**对比**：

| 平台 | 中国开发者可用？ | 接受中国买家？ | 手续费 | 提供 license 系统？ | 难度 |
|---|---|---|---|---|---|
| 爱发电 | ✅ | 仅微信/支付宝 | 5% | ❌ 需自建 | 已经在用 |
| Stripe | 需海外公司 | 部分卡 | 2.9% + $0.30 | ❌ | 高 |
| **Lemon Squeezy** | ✅（个人即可，是 MoR）| 信用卡 | 5% + $0.50 | ✅ 内置 | **中** |
| Paddle | ✅（MoR）| 信用卡 | 5% + $0.50 | ⚠️ 部分 | 中 |
| Polar | ✅ | 信用卡 | 4% | ✅ 内置 | 中 |
| Gumroad | ✅ | 信用卡 | 10% | ⚠️ 简陋 | 低 |

**MoR (Merchant of Record)** = 平台负责开发票、收增值税、合规、退款。你只管收钱。

**推荐组合**：
- **国内用户** → 继续用爱发电
- **海外用户** → 接 Lemon Squeezy（个人开发者最友好，license 系统完善）
- **登录页** = 一个简单的 landing（用 Cloudflare Pages 或 Vercel 部署一个 Astro/Next 单页），中文区按钮跳爱发电，英文区按钮跳 Lemon Squeezy

**Lemon Squeezy 的关键卖点**：他们的 license API 可以替代你现有的 D1 license 表。但**不建议**马上替换 — 你已经有了一套 working 的系统，加一个并行的就好。

### 方案 E：完整自建 dashboard（不推荐近期做）

5000+ 付费用户、做团队版/企业版的时候才需要。需要：用户登录、订单管理、订阅续费、设备管理、配额管理、客服工单。

**至少 1-2 个月一个人全职做完**。

## 3. 关于"自建网站"

你问要不要自建网站。答案分层：

| 层级 | 建议 |
|---|---|
| **landing 页**（"这是什么、为什么买、怎么买"）| ✅ **必做**（哪怕只是 GitHub Pages 上的一个静态 README） |
| **license 自助查询页** | ✅ **立刻做**（方案 B） |
| **博客 / 教程页** | ⏳ 可做可不做（小红书/即刻效果更好） |
| **用户登录 dashboard** | ❌ 暂不做（方案 E） |

**最便宜的 landing 页方案**：
- 域名：`tidelog.com` 或 `tidelog.app`（约 ¥80/年）
- 部署：Cloudflare Pages（**免费**）
- 框架：Astro / Next.js（**免费**）
- 内容：1 个首页（hero + demo GIF + 功能矩阵 + 价格 + 购买按钮）+ 1 个 `/portal` 自助查询页 + 1 个 `/privacy` 隐私政策

**总成本：¥80/年**。1 周可上线。

## 4. 引导用户付费的具体动线

不论你用什么方案，付费动线应该是这样：

```
用户点 Pro 功能（如月报）
    ↓
ProModal 弹出（已完成）
    ├─ 看到"年度 ¥49 / 终身 ¥99"对比
    ├─ 看到 7 大 Pro 功能列表
    ├─ 看到"3 设备 / 7 天退款"信任条
    ├─ 看到 [🛒 购买 Pro] 按钮
    ├─ 看到"已购买？点击激活 →"链接
    ↓
点购买 → 跳爱发电
    ↓
爱发电付款页（你不能控制 UI）
    ↓
付款成功
    ↓
【现在】 → 手动等开发者发 key（差）
【方案 B】 → 去 tidelog.com/portal 输邮箱+订单号查 key（中）
【方案 C】 → 1 分钟内收到 key 邮件（好）
    ↓
回到 Obsidian → 设置 → TideLog → 粘贴 key → 激活
    ↓
ProModal 消失，Pro 功能解锁
```

每一步都有"流失风险"。**优先优化付款→拿到 key 这一步**，因为：
- 上游已经流失了（小红书 → README → 装插件 → 触达 Pro），到付款这步已经是最高意图用户
- 这一步流失对你最痛（最接近收钱）

## 5. 我的最终建议

### 立即（这周）

✅ **保留爱发电收款**。不要换。
✅ **在 Cloudflare Worker 上加 `/portal/lookup` 和 `/portal/unbind`**（方案 B）— 1 天
✅ **加一个简单 HTML 页面挂在 Worker 上**（同域名 `/portal`）— 半天
✅ **在 ProModal 里加"已购买？查我的 key →"链接，指向 portal 页**

### 1 个月内

⏳ **买域名 tidelog.com / .app + 部署 Cloudflare Pages landing 页**
⏳ **接爱发电 webhook + 用 Resend 自动发 key 邮件**（方案 C）

### 3 个月内（如果你想做国际）

⏳ **接 Lemon Squeezy 作为海外通道**（方案 D）— 此时再考虑英文 landing

### 永远不要做

❌ **不要做用户登录 + 密码 + 注册流程**（直到 5000+ 付费用户）
❌ **不要从爱发电迁出**（除非你真的不要中国用户了）
❌ **不要自己接微信/支付宝官方支付**（合规成本极高，远不如 5% 手续费划算）

---

## 6. 一句话决策

> **加一个 `/portal` 自助查询页（方案 B）就能解决 80% 客服痛点，1 天能做完，不需要自建网站。**
> **landing 页 + 自动发 key 邮件可以排到下个月做。完整自建 dashboard 半年内都不需要。**
